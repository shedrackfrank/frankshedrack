PURPOSE: Premium, highly animated but extremely fast personal portfolio showcasing web development and cybersecurity work. Must feel human-designed and distinctive, not generic AI-generated portfolio output. Portfolio only.
BRAND MESSAGE: "Build first, then show that you understand how systems can fail." It should read as a strong software-developer portfolio first; cybersecurity shows through the About section, skills and the security case study, not through cliche hacker visuals.
TONE: professional, confident, slightly playful. Do not describe the owner as a founder in project entries.
SECTIONS: Hero, Selected Work, About (cybersecurity-leaning), Skills, Education (University of Port Harcourt only), Contact ("Get in touch"), minimal footer. No Experience, Certifications, or availability badge.
PROJECTS: 2 web projects and 1 cybersecurity project initially; architecture must scale to many more without redesign. Case-study pages are real case studies, with a card-to-page transition that feels like expansion, readable by both recruiters and technical visitors.
NAVIGATION: Home, Work, About, Skills, Contact. Desktop vertical social rail (GitHub, LinkedIn, Email only). Mobile gets a redesigned compact treatment, not a squeezed rail.
AVATAR: small circle, not a large portrait; a replaceable static asset with optimized sizes and formats; no backend for it.
VISUAL: dark by default with a carefully designed light/dark switch. Premium editorial plus restrained technical character. Near-black background with a very subtle grid/noise texture. Restrained cool teal accent, never neon green. Sans for headings and body, monospace for technical metadata. Typography-first hero with a small avatar. Avoid: fake hacker dashboards or terminals, excess gradients, blobs, glow, glassmorphism, giant counters, decorative terminal spam, template-like cards.
MOTION: polished hero entrance, project card-to-case-study transition, subtle security-inspired interaction. CSS and native browser features first; Motion only where it clearly earns its place. No continuous heavy 3D or GPU-heavy backgrounds. No sound. Respect prefers-reduced-motion. Desktop cursor: subtle Linux-style custom cursor with system-cursor fallback that never harms usability. Mobile animation is lighter and never hover-dependent.
MOBILE: first-class target. Stacked project cards, compact touch-friendly nav, intelligent type reflow, no hover-only functionality.
PERFORMANCE: static HTML wherever possible, minimal client JS, lazy-load below-the-fold images, responsive WebP/AVIF, animate mainly transform and opacity, no huge video backgrounds or unoptimized screenshots, lean DOM, lean dependencies.
